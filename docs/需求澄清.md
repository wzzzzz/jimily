## 1. 需求与目标

### 一句话需求

在现有 Jimily（记米粒）Nuxt 4 全栈记账应用中新增「账本概览」页面，使登录用户打开后能一屏看到本月收支、预算进度、最近流水、支出构成与近 6 个月趋势，并能通过现有流水弹窗快速记一笔，同时不新增后端表、不改变登录与数据隔离方式。

### 背景

- 目标仓库 `jimily` 是一个已具备完整能力的个人记账应用：Nuxt 4 + Vue 3 + PostgreSQL + Prisma，支持登录、流水、资金账户、预算、分析、分类、日历、借出、API 令牌与 AI 助手 Jimi。
- 现有用户功能分散在 `/user/flows`（流水）、`/user/analysis`（分析）、`/user/budget`（预算）、`/user/accounts`（账户）等页面；缺少一个统一的本月概览入口，用户需要在多个页面之间切换才能回答「这个月花了多少、还剩多少预算、最近记了什么」。
- 根路由 `/` 当前跳转到 `/user/jimi`（AI 助手），没有默认的账本概览页。
- 仓库 `AGENTS.md` 明确要求：定制开发应沿现有 Nuxt 全栈结构扩展，不另起一套后端或前端框架；不新建、编辑或执行 Prisma migration；文档放 `docs/`，设计方案放 `design/`，代码/脚本变更记录放 `changelog/`。

### 范围调整说明（重要）

用户最初选择「本地单用户、浏览器 localStorage」的产品形态。目标仓库实际为**多用户、登录态、PostgreSQL 全栈应用**，且仓库 `AGENTS.md` 要求沿用现有架构。为避免与现有应用冲突、重复建设或违反仓库约束，本次将「个人记账项目雏形」收敛为：

> **在现有 Jimily 应用内新增「账本概览」页面与快速记账入口，复用现有登录、流水、账户、预算、分析能力；不新建独立前后端，不引入 localStorage 单用户形态，不新增数据库表或迁移。**

该调整基于仓库代码与 `AGENTS.md` 的明确约束，已写入 PRD；如用户希望改为独立本地应用，需要另行确认并重新评估仓库约束。

### 重复性评估

- 已查询 Meego 空间 `6a64472d6c480cd93b7d33fa` 的 337 条需求，按「记账 / 账本 / 收支 / 财务 / 预算 / 消费 / 账单」检索，未发现重复或相近的未完成需求。
- 目标仓库内已有流水、分析、预算页面，但**没有统一的账本概览页**；本次为增量能力，不重复现有页面。

### 目标与成功标准

- 目标 1：提供 `/user/overview` 账本概览页，登录用户可从侧栏与移动端底栏进入。
- 目标 2：概览首屏回答「本月收入、支出、净收入、预算进度、最近流水、支出构成」六个问题。
- 目标 3：复用现有 `FlowEditDialog` 完成快速记一笔，保存后概览即时刷新。
- 目标 4：不新增数据库表/迁移、不新增运行时依赖、不改变现有接口契约。
- 成功标准 1：登录用户从任意页面进入概览不超过 2 次点击；首屏在 375px 宽度下无横向滚动。
- 成功标准 2：快速记一笔从点击到保存成功不超过 3 个主要步骤，保存后本月汇总与最近流水在 1 次刷新内更新。

## 2. 范围与业务规则

### 范围

- 做什么：
  - 新增 `/user/overview` 页面，使用现有 `public` 布局与 `auth` 中间件。
  - 月份切换：默认当前月，可查看历史月份，不可进入未来月份，提供「回到本月」。
  - 汇总卡：本月总收入、总支出、净收入、不计收支（复用 `flow/page` 返回的统计字段）。
  - 预算进度：读取当前月 `Budget`，展示预算、已用、剩余与进度条；无预算时展示引导。
  - 最近流水：展示本月最近 5 条流水，点击复用现有 `FlowEditDialog` 编辑。
  - 支出构成：按 `industryType` 聚合本月支出，展示前 6 类与占比。
  - 近 6 个月趋势：展示收入/支出柱状趋势，终点为当前所选月份。
  - 快速记账：复用现有 `FlowEditDialog`，新增成功后刷新概览。
  - 导航：侧栏与移动端底栏新增「概览」入口。
- 不做什么：
  - 不新建数据库表、字段或 Prisma migration；不改 `prisma/schema.prisma`。
  - 不改变登录、注册、JWT、用户隔离与密码哈希逻辑。
  - 不引入 localStorage 单用户形态、新后端服务或新前端框架。
  - 不重做流水、分析、预算、账户等现有页面。
  - 不改变根路由 `/` → `/user/jimi` 的跳转（本迭代保留现状）。
  - 不新增或修改 Jimi 工具、账单解析、导入导出链路。
  - 不新增图表库或 UI 组件库；复用现有 ECharts、Heroicons、Tailwind 主题。
  - 不改 `.env`、`data/`、数据库备份或账单样例。

### 核心业务规则

- 月份：格式 `YYYY-MM`；默认当前月；上一月/下一月切换；下一月不得晚于当前月；历史月份可查看。
- 汇总口径：收入、支出金额取绝对值；净收入 = 总收入 − 总支出；不计收支单独展示，不计入净收入。
- 预算：按 `Budget.month` 匹配所选月份；进度 = `used / budget`；`budget` 为空或 0 时显示「未设置预算」，不做除零。
- 最近流水：按 `day` 倒序、`id` 倒序取 5 条；点击打开编辑弹窗；保存后重新加载概览。
- 支出构成：`flowType = 支出`，按 `industryType` 聚合，按 `outSum` 降序；无数据时展示空态。
- 趋势：以所选月份为终点，展示近 6 个月的收入/支出；无数据时展示空态。
- 快速记账：复用现有 `FlowEditDialog`，默认日期为今天，流水类型/分类/账户沿用现有新增逻辑；保存成功使用现有 `Alert.success` 提示。
- 权限：所有查询必须带当前 `userId`（由 JWT 解析），不得返回其他用户数据；页面使用 `middleware: ["auth"]`。
- 时间边界：使用现有 `parseDateBoundary` 的起止语义；前端日期以本地日期 `YYYY-MM-DD` 传递。

### 边界与异常

- 空态：本月无流水时，汇总为零、最近流水为空、支出构成为空、趋势仍可展示历史。
- 无预算：预算卡展示「未设置预算」与「去设置」链接。
- 接口失败：使用现有 Toast 提示，不阻塞页面其他区块；单个区块失败不导致整页白屏。
- 加载中：首屏展示轻量骨架或加载态，避免布局抖动。
- 长文本：流水名称、分类名、账户名超长时省略；金额使用等宽数字对齐。
- 窄屏：375px 下卡片单列，底部导航 5 项不遮挡内容。
- 深色模式：沿用现有主题变量，不写死颜色。
- 不改变：现有流水页、分析页、预算页、账户页的行为与接口。

## 3. 用户与场景（概要）

- 目标用户：已登录 Jimily 的个人记账用户。
- 使用场景：
  - 打开应用后先看本月收支与预算进度。
  - 想起一笔消费，直接在概览页点「记一笔」。
  - 查看最近流水，点击某条补改分类或金额。
  - 从概览跳转到流水、分析或预算页面深入查看。
- 关键路径概要：
  1. 登录 → 侧栏/底栏点击「概览」。
  2. 查看本月汇总、预算、最近流水、支出构成与趋势。
  3. 点击「记一笔」→ 在现有流水弹窗填写 → 保存 → 概览刷新。
  4. 点击「查看全部」/「数据分析」/「预算管理」进入现有页面。
